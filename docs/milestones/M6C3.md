## Purpose

M6C3 adds the smallest bounded runtime/configuration owner above the already
validated M6C1 polygon geometry and M6C2 permitted-area union. It deliberately
stops before production composition-root integration.

The new `GeofenceRuntime` owns:

- one volatile bounded copy of the currently applied permitted polygons;
- all-or-nothing replacement of that runtime copy after complete validation;
- one latest valid `PermittedAreaAssessment` plus caller-owned observation
  capture time;
- explicit clear semantics.

It does **not** own GNSS acquisition, GNSS quality/freshness, generic location
source arbitration, durable configuration, NEAR_FENCE distance, hysteresis,
repeated-fix confirmation, FREE_GRAZE, LOST, RF events or alarms.

## Runtime resource boundary

The current M6C3 runtime budget is intentionally small and explicit:

```text
maximum permitted areas:          8
maximum total effective vertices: 64
```

This is a volatile runtime resource budget, not a frozen public product limit or
a durable storage format.

M6C1 permits an optional explicit final vertex equal to the first vertex. M6C3
canonicalizes that redundant closing point when it takes ownership, so a polygon
with 64 effective vertices plus the repeated closing point still satisfies the
64-effective-vertex runtime budget. This preserves M6C1 semantics instead of
silently narrowing them at the runtime boundary.

The owned geometry consumes fixed memory only; no heap allocation is introduced.
Configuration validation remains bounded. Repeated point assessment still uses
the existing M6C2 fail-closed validation/composition path; no second geometry
implementation is introduced.

`GeofenceRuntime` is intentionally non-copyable and non-movable. Its internal
area views point into its own fixed vertex buffer, so default object copying would
create invalid ownership/lifetime semantics even though the original object was
correct. The type therefore rejects accidental copies at compile time.

## Replacement and failure semantics

`configure()` validates and sizes the complete caller-owned candidate before
changing active state.

- invalid/empty candidate -> reject;
- more than 8 areas -> reject;
- any malformed polygon -> reject;
- any per-polygon or aggregate effective-vertex budget overflow -> reject;
- successful candidate -> copy into runtime-owned fixed memory and clear the old
  assessment because it belonged to the previous geometry.

A rejected replacement preserves the previous known-good configuration **and**
its latest valid assessment and observation time. There is no partial apply.

`clear()` explicitly removes runtime configuration and invalidates the assessment.
No persistence is implied.

## Accepted-position boundary

`observeAcceptedPosition()` accepts only `GeoPointE7` plus a caller-owned local
capture timestamp. The caller must already have accepted that observation under
the active location/tracking policy.

This boundary is deliberately not typed as `GnssFix`. `GnssFix` is a portable
GNSS observation, while geofence is a location-consuming service that must also
remain usable with future PHONE/MANUAL/fixed location sources without fabricating
GNSS fields or bypassing the owner. M6C3 therefore does not inspect HDOP,
satellite count, age or source ownership and cannot create a competing freshness
policy.

A valid point updates the latched assessment and stores the supplied capture time.
An unsupported/invalid coordinate returns `kInvalidPoint` and does not erase the
last valid assessment. A defensive impossible-invalid copied configuration
returns `kConfigFault` rather than inventing OUTSIDE.

This API is a seam for later composition-root integration. In this slice there is
no authoritative geofence configuration source and no production `main.cpp`
wiring, so no field geofence behavior is claimed.

### P2 — FIXED: geofence runtime was coupled to `GnssFix`

The initial M6C3 API accepted `observeAcceptedFix(const GnssFix&)`. That made the
geofence runtime depend on a GNSS-specific value even though architecture rules
require Location and GNSS to remain separate. A later PHONE/MANUAL/fixed location
source would otherwise need to fabricate a `GnssFix` or bypass the same geofence
owner.

Minimal fix: the runtime now accepts `GeoPointE7` plus caller-owned capture time.
No generic Location framework was invented. GNSS/source/freshness acceptance
remains outside the geofence owner.

Regression tests were updated to freeze this source-neutral API and to verify
that resource-bound rejection preserves the prior assessment/time as well as the
prior geometry.

### P3 — non-blocking: repeated geometry validation cost

`configure()` validates owned geometry, while the retained M6C2 assessment path
validates polygons again on observations and the one-polygon classifier validates
again internally. The work is bounded by 8 areas / 64 effective vertices and the
slice is not production-wired, so this is not a merge blocker for M6C3.

Before high-frequency production geofence evaluation is enabled, CPU/power cost
should be measured and the geometry API may be reviewed for a safe already-
validated fast path. Do not duplicate geometry logic merely to optimize this
prematurely.
