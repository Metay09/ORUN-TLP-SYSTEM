# M4P1 — History store-forward delivery contract

Status: **DESIGN READY FOR INDEPENDENT AUDIT — NO RUNTIME / WIRE CHANGE.**

Baseline: `main@d25d51d597735cc6611820e60ac6084716a0090e`.

Branch: `design/history-store-forward-delivery-contract`.

## 1. Purpose

M4 implemented persistent store-first POSITION history but deliberately left
automatic backlog replay and trusted delivery confirmation unimplemented.

M4P1 defines the missing product/runtime contract before replay code is added.
The governing architecture record is:

`docs/architecture/ORUN_HISTORY_STORE_FORWARD_DELIVERY.md`.

## 2. Key decisions

- backlog is not assigned to one fixed gateway;
- fixed and MOBILE gateways may carry the same logical observation;
- downstream duplicate path observations converge on one application observation;
- `TX_DONE`, relay completion and gateway RF receipt are not delivery;
- initial tracker history release requires authenticated `BACKEND_DURABLE`
  receipt evidence;
- replay is oldest-undelivered first with one distinct outstanding backlog
  observation;
- receipt progress is contiguous in RAM before durable checkpoint;
- per-record `markDeliveredThrough()` / replay-cursor persistence is prohibited
  because History format v3 has only four state slots per active page;
- reboot before checkpoint may cause duplicate replay; duplicate work is
  preferable to premature deletion;
- blind v1 POSITION replay is not accepted as a production historical-data
  contract because v1 lacks explicit replay/history context and can lack
  trustworthy UTC;
- production backend dedupe/receipt requires an explicit History observation
  stream incarnation so a destructive History reset cannot reuse the same
  logical observation namespace.

## 3. Concrete implementation blocker found

History format v3 reserves only:

```text
kStateSlotsPerPage = 4
```

A naive implementation that writes `delivered_through` after every ACK can
consume all four state slots after four receipts and trigger metadata-driven
page rotation/erase independent of normal record capacity.

Therefore the existing delivery APIs are primitives, not a safe per-packet
runtime policy.

This is the principal reason M4P1 is a contract/audit slice rather than a quick
`getNextBacklog() -> send -> markDeliveredThrough()` production patch.

## 6. Audit focus

Independent review should specifically test whether:

- BACKEND_DURABLE is the correct initial tracker-release scope;
- oldest-first exact receipt correlation prevents cumulative-ACK gap loss;
- History incarnation is sufficient to prevent post-reset backend identity
  collision;
- the checkpoint approach cannot cause metadata-driven history destruction;
- reboot semantics are duplicate-safe;
- fixed and MOBILE gateways remain transport/capability variants rather than
  ownership identities;
- historical replay cannot be displayed as live merely because it arrived now;
- the design composes with the current TLP v2 security direction without
  inventing a second security system;
- replay scheduling cannot starve live/critical traffic or create unbounded RF
  bursts.
