# M6B2 — Activity feature eligibility boundary

Status: **SOFTWARE-VALIDATED; HOST-ONLY; NOT PRODUCTION-INTEGRATED**.

Stacked baseline: `feat/m6b-activity-core@8353e18785cd16d62c43f0c0d5f63418c96a3d0f`.
Branch: `feat/m6b2-activity-quality`.

## Purpose

M6B2 adds the small quality gate that sits between deterministic feature extraction and any later behavior classifier. The goal is to make it impossible for incomplete, timing-invalid or internally inconsistent feature windows to be treated as classifier-ready by accident.

The boundary remains pure and host-only. It does not read hardware, alter `main.cpp`, enable continuous sampling, define RESTING/GRAZING/WALKING thresholds, write flash or transmit RF.

## Eligibility contract

A feature window is classifier-eligible only when all structural facts agree:

```text
complete == true
sample_count == activity_config::kWindowSampleCount
timing_continuous == true
timing_discontinuities == 0
duration_ms is consistent with N-1 intervals inside the current timing sanity band
```

For the current 50-sample seed and M6B1 timing band of 50..300 ms per adjacent interval, accepted aggregate duration is:

```text
49 * 50 ms <= duration_ms <= 49 * 300 ms
2450 ms     <= duration_ms <= 14700 ms
```

Any malformed/inconsistent externally-constructed feature object fails closed. This is a data-quality contract, not an animal-behavior decision.

The current reason surface distinguishes:

- usable;
- incomplete/structurally incomplete;
- timing-discontinuous/inconsistent timing state, including impossible aggregate duration.

No magnitude, variance or motion threshold is used here because those values belong to later classifier/field-validation policy.

## Ownership and compatibility

`activity_quality.*` owns only eligibility of already-computed local features. It does not own sensor presence, service enablement, activity classification, RF, storage, power or location.

```text
Protocol/TLP v1: unchanged
RF/airtime:       unchanged
Storage/flash:    unchanged
GNSS:             unchanged
RAK1904 driver:   unchanged
main.cpp runtime: unchanged
RequestedConfig:  unchanged
Power ownership:  unchanged
```

## Review note — aggregate duration consistency

Initial M6B2 checked sample count and the two explicit timing fields, but an externally built `ActivityWindowFeatures` object could still claim a complete, continuous 50-sample window with `duration_ms = 0` or another impossible total duration. A later classifier should not have to trust contradictory metadata.

The quality gate now derives minimum/maximum aggregate duration from the same `kMinimumInterSampleGapMs` / `kMaximumInterSampleGapMs` bounds as M6B1 and rejects contradictions as `kTimingInvalid`. This does not add a new behavior threshold and does not alter the feature extractor.
