## 1. Purpose

M4P1 froze the store-forward safety semantics and independent review closure.

M4P2 is the first small SF1 runtime foundation. It does **not** implement
backlog RF replay, secure receipt wire bytes, backend ingestion or gateway
custody.

This slice adds only:

1. a RAM-only contiguous authenticated-delivery watermark primitive;
2. a durable delivery checkpoint operation which refuses to rotate/erase a
   History page when all four state slots are consumed;
3. production backlog selection which no longer trusts persisted
   `replay_cursor` as a skip bound;
4. host regression coverage for metadata-only erase prevention, reboot
   duplicate safety, numeric/actual-record contiguity and legacy cursor
   non-authority.

## 2. Ownership / security boundary

HistoryStore does not authenticate receipts.

A future reviewed A2D owner must authenticate and authorize a
BACKEND_DURABLE receipt first, then pass only an explicit retained History
identity to `acknowledgeDeliveredRecord()`.

This slice therefore does not create a new crypto/security path and does not
weaken the M4P1 backend-authority rule.

## 3. RAM progress

`acknowledgeDeliveredRecord(identity)` is RAM-only.

It advances only when `identity` is the next actual retained History record
after the current RAM watermark. Numeric ticket gaps are irrelevant because the
check uses the record journal itself.

Duplicate/late identities at or below the already acknowledged prefix are
idempotent and cannot regress state.

After reboot, RAM progress resets to the durable `delivered_through`; any
uncheckpointed receipts may be replayed safely.

SF3's later bounded selective acknowledged-ID set is intentionally **not**
implemented here.

## 4. Durable checkpoint

`checkpointAcknowledgedDelivery()` persists only the current contiguous RAM
watermark.

When the active page has no free state slot, it returns
`kDeferredNoStateSlot` and performs no flash mutation.

The low-level `startState()` path is also hardened so state metadata can never
call `startNewPage(false)`. Therefore:

```text
metadata-only History page erase count = 0
```

A normal record-capacity-driven page transition may create a page with fresh
state slots; a later retry can then checkpoint without an additional erase.

The legacy `markDeliveredThrough()` API is retained as a compatibility wrapper
over RAM acknowledgement plus the safe checkpoint policy.

## 5. Legacy replay cursor

Persisted `replay_cursor` remains readable only as legacy development state.

`getNextBacklog()` now starts from durable `delivered_through` and cannot
skip an undelivered record because of a stale cursor. A successful trusted
checkpoint clears replay_cursor in the newly written state record.

No automatic migration/erase is introduced by this slice.

## 11. Independent focused audit

Independent audit of
`117950e4e3f73625015c45a409dbe9e82554387f` returned:

```text
PASS WITH FIXES
BLOCKER 0
HIGH    0
MEDIUM  2
LOW     5
```

The reviewer found no data-loss path. Failure cases remained duplicate-safe or
deferred progress, but two merge-blocking correctness/diagnostic issues were
identified.

### MEDIUM-1 — acknowledged record overwritten before checkpoint

Original behavior re-looked-up `acknowledged_through_` at checkpoint time.
If normal capacity rotation erased a record after its authenticated receipt had
already entered RAM, checkpoint retries became permanently `kRejected`.

Fix:

- receipt admission still requires the exact next retained actual record;
- checkpoint no longer requires the already-admitted identity to remain
  physically present;
- capacity erase does not revoke a previously authenticated BACKEND_DURABLE
  fact;
- architecture text now makes this distinction explicit.

### MEDIUM-2 — capacity loss not separated from confirmed release

Original `overwritten` counted every erased valid record together.

Fix:

- `Diagnostics::capacity_lost_undelivered` records valid records erased above
  the highest RAM/durable confirmed watermark;
- the count is captured before erase but published only after the physical erase
  succeeds;
- already acknowledged/durable records are not reported as undelivered
  capacity loss.

### LOW hardening

- acknowledgement scan is fail-closed if a slot recovered as valid cannot be
  read/decoded, so a transient/read-corrupt slot cannot be silently skipped;
- legacy `markDeliveredThrough()` checks safe checkpoint capacity before
  advancing RAM, avoiding false-return-with-new-RAM-progress;
- the dead `state_after_new_page_` path is removed;
- persistent tests are added for capacity overwrite, strict read failure,
  positive numeric ticket gaps, checkpoint power-cut boundaries and legacy
  deferred-call RAM semantics;
- richer acknowledgement result typing remains intentionally deferred until SF3
  introduces a production receipt caller. Until then the bool API has no
  production caller and `false` must not be interpreted as a final remote
  rejection.

after these fixes. Then perform focused independent final verification before
