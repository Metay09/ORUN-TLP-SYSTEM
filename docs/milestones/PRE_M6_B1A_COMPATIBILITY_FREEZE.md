## Legacy RAK identity evidence

Pinned dependency: `SX126x-Arduino@2.0.32`, installed at
`firmware/.pio/libdeps/rak4630/SX126x-Arduino/src/boards/mcu/nrf52832/board.cpp`.
Despite the directory name, its `NRF52_SERIES` implementation serves this nRF52840
build. The corresponding compiled object exports `BoardGetUniqueId`; inspected
ARM object code agrees with the source register loads and byte stores.
Source SHA-256: `9e63105477df9bd0a99c75e7ae1fea6fd9f8e1fba6e2b28b806710cb9e5fafa1`.

- ID1 is the factory word at `0x10000060` (DEVICEID[0]); ID2 is at
  `0x10000064` (DEVICEID[1]). The chip's memory byte order is little-endian.
- BoardGetUniqueId returns ID2 most-significant byte first in `id[0..3]`,
  then ID1 most-significant byte first in `id[4..7]`.
- Production `boardUniqueIdToUint64`, called by `RadioManager::begin`, folds
  those eight bytes in index order, making `id[0]` most significant.
  The resulting value is mathematically `(uint64(ID2) << 32) | ID1`.
- Production Serial prints `%08lX%08lX`, high uint32 then low uint32, each cast
  to unsigned long. This preserves 16 uppercase hex digits and leading zeros
  without the target nano-printf unsupported long-long conversion.

| Known device | ID1 word / little-endian bytes at 0x10000060 | ID2 word / little-endian bytes at 0x10000064 | Board bytes / expected uint64 hex |
| --- | --- | --- | --- |
| A | `4B275BA5` / `A5 5B 27 4B` | `09A462BD` / `BD 62 A4 09` | `09 A4 62 BD 4B 27 5B A5` / `09A462BD4B275BA5` |
| B | `71531AA3` / `A3 1A 53 71` | `0E8ADE7E` / `7E DE 8A 0E` | `0E 8A DE 7E 71 53 1A A3` / `0E8ADE7E71531AA3` |

The word values above are derived from the previously observed IDs and audited
mapping; this task did not read physical factory registers. A/B are specific
legacy compatibility evidence, not universal IDs or future-platform assumptions.

The new R2 identity test supplies literal eight-byte fixtures through the existing
BoardGetUniqueId host stub, calls real `RadioManager::begin`, asserts literal
uint64 expectations, and checks real production POSITION serial output against
literal A/B strings. It therefore exercises the existing private pure conversion
through its public caller without extracting or changing production code. The
hardware register-to-byte implementation is source/object-audited, not executed
on host. Existing serial edge cases and long-long compile guard remain intact.

Unchanged startup regressions execute real setup/loop/history with mutex, gate,
queue and LoRa startup failures plus successful boot in separate processes.
They assert identity read before history recovery, no initial erase/write or
history mutation, continued local fresh-fix appends under the correct identity,
and no TX/RX after failed radio startup. These retain the startup safety guarantee
under the host model; B1A does not replace them with a standalone mapping test.
