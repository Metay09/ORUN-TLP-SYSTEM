# M4 — Persistent POSITION history and store-first foundation

## Result

M4 retains the universal firmware binary and adds a compact, persistent,
circular POSITION journal with store-first live transmission. Firmware version
is `0.4.0-alpha`. M3 GNSS scheduling, fresh-fix rules, power policy, radio RX,
Device ID and the 34-byte M2 POSITION wire format remain unchanged.

Fresh valid fix → encode unchanged POSITION semantics → persist/readback
→ one live LoRa attempt. Storage failure suppresses normal POSITION TX. No ACK,
relay, BLE provisioning, geofence, accelerometer or M5 behavior is added.

## Storage ownership and backend

The installed `nrf52840_s140_v6.ld` application ends at `0xED000`. The core
`InternalFileSystem.cpp` reserves `0xED000..0xF4000` as seven InternalFS pages.
ORUN TLP now uses this exact core InternalFS partition exclusively as its raw
journal. It must not be mounted as InternalFS/LittleFS concurrently. Build and
runtime guards verify the boundary/geometry and reject a linked `InternalFS`
object. Future InternalFS use requires explicit backend repartitioning and data
migration. Firmware, SoftDevice and bootloader areas are untouched.

Post-M5 storage repair R1 uses Nordic `sd_flash_write` and
`sd_flash_page_erase` directly and removes the incompatible Adafruit page cache
from the linked image. R1.1 supports synchronous SoftDevice-disabled operations
only. Enabled SoftDevice is rejected before issuing any program/erase call;
there is no semaphore, callback or timeout path. Aligned writes are page-bounded
and are read back before success. SoftDevice-enabled persistent storage is an
M7 prerequisite: Bluefruit event routing and InternalFS ownership must be
designed together before BLE startup can safely coexist with the raw journal.
A normal record uses two program operations and zero erases; record-driven page
rotation erases only the reclaimed page once. No NVMC register hack is used.

## Journal, recovery and capacity

Seven self-describing 4,096-byte pages are used: 352-byte header area, 36-byte
records, exactly 104 records/page, **728 usable POSITION records**. At 96
positions/day (15 minutes), maximum retention is **7.5833 days**. A wrap can
temporarily leave 624–728 records because an old 104-record page is replaced.
The 14-day target needs 1,344 records and is **not met** by the safe existing
28 KiB InternalFS partition; no unsafe flash expansion was made.

Records preserve original sequence, epoch, latitude, longitude, altitude, HDOP,
satellites and flags. Device ID/protocol/type are reconstructed from fixed
context. Local format v3 identifies the corrected zero-based ticket high word
(`identity - 1`). V2-only development journals fail initialization without erase
and require an explicit development partition reset; no migration is performed.
The wire packet remains unchanged. The stored high word belongs to that ticket,
so the uint32 wire-sequence boundary reconstructs without a double carry.
Explicit CRC-32/ISO-HDLC and final commit words protect records, headers,
sequence reservations and cursor state; no compiler layout is persisted.

On boot only the partition is scanned. Valid page generations reconstruct
history without global metadata dependency. Torn compact records are skipped;
append-only commits do not rewrite earlier records. During rotation only the
reclaimed oldest page is exposed to erase interruption, while the other six
pages recover. Torn replacement page headers leave those pages intact. Erased virgin
storage starts automatically. A first-init cut before any valid header is
treated as empty exclusive ORUN storage, including bit-partial magic/CRC/commit,
and page zero is reinitialized. Existing valid v3 pages always prevent this
empty reset. Recognizable v2 development headers are explicitly refused.

TEST and POSITION share 256-ticket durable reservations stored in page headers.
Boot skips the old reservation and commits the next block before issuing a
ticket, avoiding reboot/power-loss reuse. Exhaustion automatically commits the
next block before exposing its first ticket, while the old block's last ticket
remains appendable even after allocation exhausts the block. `uint32_t`
sequence wrapping keeps its existing wire behavior.

## Delivery/backlog and diagnostics

`TX_DONE != DELIVERED`. Neither TX_DONE, TX timeout nor a local live send
attempt changes durable delivery state or deletes history. `HistoryStore`
provides oldest/newest/read-after, explicit future delivered-through and replay
cursor APIs; M4 has no BASE confirmation caller and no automatic RF replay.
Live data therefore never waits behind a historical TX loop.

Runtime diagnostics include appended records, append failures, recovery
corruptions, overwritten records, state-write failures, flow storage drops, TX
attempts, local send failures and TX timeouts. Counters are not put into the
wire packet. See [M4_FLASH_JOURNAL.md](../storage/M4_FLASH_JOURNAL.md) for
exact byte layout and the fault model.

## Verification

```sh
bash firmware/tests/run_host_tests.sh
cd firmware && pio run
git diff --check
```

M3 deterministic tests and M4 sanitizer-backed journal tests pass. The repaired
fault backend models page erase and `1 -> 0` NOR programming. Tests cover
virgin storage, body/commit/header/reservation cuts, old-record and sequence
preservation, readback failures, wear counts, circular wrap, CRC corruption,
identity boundaries, reservation exhaustion, PositionFlow terminal failure,
cursor persistence and store-before-TX/no-delivery semantics.

Final `pio run` result: **SUCCESS**.

- RAM: **12,468 / 248,832 bytes (5.0%)**
- Flash: **132,608 / 815,104 bytes (16.3%)**

Physical validation remains pending: first format, repeated reboot recovery,
power removal during all commit/erase phases, hundreds/thousands of records,
actual retention/wrap, current/endurance, enabled-SoftDevice fail-safe refusal,
LoRa RX/TX and GNSS timing during core flash operations. No such behavior is
claimed verified without hardware.
