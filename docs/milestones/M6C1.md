# M6C1 — Host-only geofence polygon geometry

Status: **IN PROGRESS; HOST-ONLY; NOT PRODUCTION-INTEGRATED**.

Stacked baseline: `feat/m6b2-activity-quality@5400977c971cf118c65a134515fc75d4b8dec00e`.
Branch: `feat/m6c1-geofence-geometry`.

## Purpose

M6C1 starts only the deterministic geometry layer needed by the later local geofence service. It answers one narrow question: for a validated simple polygon and an E7 coordinate point, is the point inside, exactly on the polygon boundary, or outside?

This slice deliberately does **not** consume `GnssFix` directly and does not introduce a generic Location abstraction. The geometry-specific `GeoPointE7` value is only a pair of coordinates. Future M6C integration must hand it an already accepted fresh position through the correct location/tracking ownership boundary rather than let geometry own GNSS freshness or source arbitration.

## Geometry contract

M6C1 supports:

- simple polygons with 3..64 effective vertices;
- clockwise or counter-clockwise winding;
- concave polygons;
- implicit closing edge or an explicit final vertex equal to the first;
- explicit boundary result instead of silently treating an edge point as inside or outside;
- deterministic integer-only containment using a winding-number test;
- no dynamic allocation.

Validation fails closed for:

- null/too-short/too-long polygon input;
- latitude/longitude outside legal coordinate ranges;
- adjacent duplicate vertices;
- zero-area/degenerate polygons;
- self-intersecting polygons;
- polygons whose latitude or longitude span exceeds the current bounded geometry domain.

Invalid query coordinates are also distinguished from a valid point that is merely outside the polygon.

## Arithmetic safety and current span bound

Global E7 coordinates can make naïve cross-product arithmetic overflow signed 64-bit. M6C1 therefore validates a field-scale polygon span before orientation/area operations and translates area calculations around the first vertex.

Current bound:

```text
maximum latitude span  = 100,000,000 E7 units = 10 degrees
maximum longitude span = 100,000,000 E7 units = 10 degrees
maximum effective vertices = 64
```

This is an arithmetic-safety/domain bound, not a livestock-product target and not a claim that 10-degree fences are useful. It is intentionally far larger than expected farm geofences while keeping all current signed-64-bit cross products and accumulated shoelace area bounded. Antimeridian-spanning or global polygons are rejected rather than approximated silently; support for them would require an explicit future geometry model.

## Deliberate non-goals

M6C1 does not implement or claim:

- `INSIDE / NEAR_FENCE / OUTSIDE` operational state;
- distance-to-fence in meters;
- GNSS quality/freshness checks;
- repeated-fix confirmation or hysteresis;
- multiple-permitted-area orchestration;
- FREE_GRAZE;
- LOST/contact logic;
- geofence persistence/configuration storage;
- RF events or ACKs;
- `main.cpp` runtime integration.

`GeofencePointRelation::kBoundary` is geometry truth only. A later reviewed service layer will decide how boundary and near-fence distance map into operational state.

## Ownership and compatibility

```text
geofence_geometry.* -> polygon validity + point relation only
location/tracking    -> accepted fresh position (future integration owner)
geofence service     -> near/outside policy, hysteresis, multiple areas (later)
network/radio        -> unchanged
persistence          -> unchanged
```

Compatibility impact for M6C1:

```text
Protocol/TLP v1: unchanged
RF/airtime:       unchanged
Storage/flash:    unchanged
GNSS:             unchanged
RAK1904/activity: unchanged
main.cpp runtime: unchanged
RequestedConfig:  unchanged
Power ownership:  unchanged
```

## Validation plan

The host suite must cover at least:

- square inside/boundary/outside;
- clockwise/counter-clockwise equivalence;
- concave polygon notch remains outside;
- explicit closing vertex;
- malformed polygon rejection;
- self-intersection rejection;
- invalid query coordinate distinction;
- translated real-world-scale coordinates;
- local polygon arithmetic near legal coordinate extremes.

The test is compiled with the existing `gnu++11`, `-Wall -Wextra -Werror`, ASan/UBSan host profile. A RAK4630 production build is required before software closure because `geofence_geometry.cpp` sits in the production source tree even though it is not yet referenced by `main.cpp`.

No firmware upload or physical hardware validation is required for M6C1 itself because the slice is pure geometry and not runtime-integrated.
