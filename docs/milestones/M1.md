# M1 — Private LoRa P2P TEST packets

## Objective

Provide one universal RAK4630/RAK4631 firmware binary that continuously
receives and periodically transmits compact ORUN TLP TEST packets over private
LoRa P2P. RX output includes source ID, sequence number, packet type, RSSI,
and SNR at 115200 baud.

## Implementation summary

- Added a minimal `RadioManager` using the RAK4630-specific SX1262 hardware
  initialization supplied by the radio library; no local pin or SPI settings
  were added.
- Centralized the M1 RF defaults: 869.525 MHz, 14 dBm configured conducted
  TX power, 125 kHz, SF11, 4/5, 8-symbol preamble, CRC on, explicit header,
  non-inverted IQ, and private sync word `0x1424`.
- Explicitly writes sync word `0x1424` with the driver's
  `SetCustomSyncWord()` API, reads it back through `GetSyncWord()`, and logs
  the applied RF profile at boot. This standard private value separates M1
  from the public `0x3444` LoRa sync word; it is not authentication.
- SX126x-Arduino 2.0.32 automatically enables Low Data Rate Optimization for
  this SF11/BW125 profile in both TX and RX setup, so M1 uses no manual
  `EnforceLowDRopt()` override.
- Keeps continuous RX between asynchronous transmissions.
- Added a 30-second M1 test cadence with a hardware-ID-derived initial offset
  and per-packet deterministic jitter. This is only collision reduction for
  the two-node test, not a MAC or tracker reporting policy.
- Added explicit byte-level TEST packet serialization and validation; raw C++
  structs are never sent over LoRa.
- Device ID uses the eight-byte nRF52840 factory hardware ID returned by
  `BoardGetUniqueId()` and is encoded as an unsigned 64-bit big-endian value.
- Raised the firmware version to `0.2.0-alpha-m1`.

## Radio library

`beegee-tokyo/SX126x-Arduino@2.0.32` is used. The vendor-provided RAKWireless
PlatformIO configuration already selects this maintained SX126x library, and
its official WisBlock P2P and RAK4631 examples provide `lora_rak4630_init()`,
which contains the correct RAK4630 SX1262 pin, SPI, TCXO, and antenna-switch
setup. The implementation uses its P2P `Radio` API only; it does not use
LoRaWAN functionality.

## TEST packet format summary

The fixed 18-byte TLP packet is version `0x01`, type `0x01` (`TEST`), followed
by the 64-bit source device ID, a 32-bit sequence number, and a 32-bit uptime
value. Every multi-byte field is big-endian. The complete byte layout is in
[`protocol/M1_TEST_PACKET.md`](../../protocol/M1_TEST_PACKET.md).

## Build command

```sh
cd firmware
pio run
```

## Build result

`pio run` completed successfully for the `rak4630` environment.

- RAM: 9,496 bytes / 248,832 bytes (3.8%)
- Flash: 76,756 bytes / 815,104 bytes (9.4%)

The third-party library emits existing compile warnings for its RAK11300 timer
source and an informational RAK4630 selection warning; the ORUN firmware
sources compile successfully.

## Physical hardware validation still required

- Upload this same binary to two RAK4630/RAK4631 nodes with suitable 868 MHz
  antennas and observe each node's `TX` and peer `RX` lines at 115200 baud.
- Confirm the configured RF settings and private-network interoperability over
  the intended range and terrain.
- Verify conducted TX power, installed-antenna gain, ERP, duty-cycle limits,
  and all other applicable local regulations before field operation.

## Known issues

- Physical LoRa operation has not been tested; build success is not proof of
  radio communication on hardware.
- There is intentionally no ACK/retry, relay, authentication/encryption,
  duplicate tracking, configuration persistence, or power policy in M1.
